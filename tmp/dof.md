Definition of finished (phase 11):

Serverless profile, branch `p11-search` (worktree `ferropress-wt/p11-search`), landed on `lambda-port`.

1. `crates/cms-search` (domain layer, deps: serde, serde_json, sha2, thiserror only):
   - `Document` model: id, title, excerpt (the raw excerpt column, which is what the reference matches), content text with markup removed, permalink, date (`YYYY-MM-DD hh:mm:ss` local post date), post type.
   - `build(docs) -> Built { key, bytes }`: compact JSON index, deterministic bytes, key `search/<sha256 hex>.json` (content-addressed under the site prefix).
   - `Index::from_slice(bytes)` decodes it; malformed bytes are an error, not an empty index.
   - `Terms::parse(s)` reproduces the reference's term splitting: quoted phrases, separators (space, tab, comma, plus), quote trimming, single ASCII letters and single dashes dropped, the reference's default stopword list, the term "0" dropped, sentence fallback when nothing is left or more than 9 terms remain, CR/LF removed.
   - `Index::search(&Terms, page) -> Page { hits, total, pages }`: AND across terms, each included term a case-insensitive substring of title OR excerpt OR content, each `-`-prefixed term absent from all three; empty `s` matches everything; ordering for more than one raw term: sentence in title (1), all included terms in title when fewer than 7 (2), any included term in title when 2..6 (3), sentence in excerpt (4), sentence in content (5), rest (6), with sentence ranks skipped when `s` has a dash at its start or after whitespace; for one raw term: title match first; then date descending (id descending tiebreak); no relevance ordering when no term is included. 10 per page, page numbers from 1.
   - Contract-style tests encode each ordering rank, exclusion, phrase, stopword, sentence fallback and paging case from the reference behavior; unit tests for every public fn and error path.
2. `apps/lambda-search`: Function URL event in, response out; loads the index once per warm container from the `SEARCH` route item (`RouteKey "SEARCH"`, `Content::Object { body }`) through the existing `cms_readmodel::{RouteTable, Blobs}` ports and reloads only when the item's key changes; answers `<base>?s=...&paged=N` with an HTML results page assembled into the home route's theme shell at the body mark (escaped title, results list linking permalinks, excerpt, next/previous links, "nothing found" body), and `<base>wp-json/wp/v2/search?search=&page=&per_page=` with the reference REST search JSON shape (`id`, `title`, `url`, `type`, `subtype`) plus `X-WP-Total` / `X-WP-TotalPages`; out-of-range REST page is 400 `rest_post_invalid_page_number`. Short edge TTL (`s-maxage=300`). Tests use in-process fake ports.
3. `deploy/aws/cdk/functions/route-search.js`: CloudFront Function (JS runtime 2.0) that selects the search origin when query `s` is present or the path ends in `/wp-json/wp/v2/search`; origin id substituted by the CDK app; tested with `node --test` (no npm deps).
4. Gate per touched crate: fmt check, clippy pedantic `-D warnings` all targets/features, tests, rustdoc `-D warnings`; layers registered. Coverage: `cargo llvm-cov` is not installed on this machine, so coverage is not measured (reported, not claimed).
5. Reference-lab comparison: the lab needs Docker, which this phase must not run.
